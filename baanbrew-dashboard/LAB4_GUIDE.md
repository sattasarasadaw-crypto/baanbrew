### Lab 4.1 · RFM (45 นาที)

**R**ecency ไม่ได้มากี่วัน · **F**requency กี่บิล · **M**onetary ซื้อรวมเท่าไร แต่ละตัวให้คะแนน 1–5 ตามเปอร์เซ็นไทล์ แล้วตั้งชื่อกลุ่มจากคะแนน R และ F

| กลุ่ม | กติกา (ตรวจจากบนลงล่าง) | ควรทำอะไร |
|---|---|---|
| ลูกค้าชั้นยอด Champions | R ≥ 4 และ F ≥ 4 | สิทธิพิเศษ ชวนลองเมนูใหม่ |
| ลูกค้าประจำ Loyal | R ≥ 3 และ F ≥ 4 | สะสมแต้มให้ขึ้นเป็นชั้นยอด |
| ลูกค้าใหม่ New | R ≥ 4 และ F ≤ 2 | คูปองครั้งที่ 2 ใน 14 วัน |
| เสี่ยงหาย At Risk | R ≤ 2 และ F ≥ 3 | ดึงกลับด่วน |
| หายไปแล้ว Lost | R ≤ 2 | ส่งข้อความครั้งเดียว |
| ต้องดูแล Need Attention | ที่เหลือ | โปรฯ ตามเมนูที่เคยซื้อ |

1. `npm test` → ดู test ของ `rfm` ที่แดง → **Prompt 4.1A** จนเขียว
2. `npm run dev` → `http://localhost:5173/?demo` แท็บ **ลูกค้า & เมนู** (โหมดสาธิตคำนวณในเบราว์เซอร์ ไม่ใช้โควตา)
3. **Prompt 4.1B** เจาะดูรายชื่อ + ดาวน์โหลด CSV
4. commit + push → ดูบน Preview (ส่วน RFM จะขึ้นหลังรัน pipeline ใน Lab 4.2)

✅ **จุดตรวจ 4.1:** Champions **455 คน ทำยอด 39%** · At Risk **521 คน ทำยอด 27%** · CSV กลุ่มชั้นยอด 455 แถว

คำถามชวนคิด: ถ้ามีงบส่ง SMS ได้ 500 ข้อความ ควรส่งกลุ่มไหน เพราะอะไร

> ทำไมใช้ GitHub Actions ไม่ใช้ Cloud Functions?
